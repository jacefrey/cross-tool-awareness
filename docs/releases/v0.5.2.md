## I11 in one paragraph

`sqlite_master` objects were classified as "unknown" only when their names carried an awareness-namespace prefix. A user-created `UNIQUE` index or `AFTER INSERT` trigger on `targeted_deliveries` with any other name passed the exact-source check, and the hop's table rebuild destroyed it while `apply` returned `applied`: a duplicate the database used to reject was then accepted, and inserts stopped being audited. The collector now reads `tbl_name` and refuses any non-managed index or trigger attached to a managed table, before the first backup, again under each hop's write lock, and in `rollback` before any drop. SQLite internal indexes and objects on unrelated bridge-owned tables stay permitted.

## API deltas since v0.5.1

- `apply` and `rollback` additionally return `refused` (reason `unknown managed-namespace artifacts: [...]`) when any non-managed index or trigger is attached to a managed table, whatever its name. Operators who intentionally added such objects must drop them (or migrate them by hand after a backup) before upgrading; the package does not recreate unknown SQL.

Everything else is as listed in [v0.5.1.md](v0.5.1.md) § "API deltas since the withdrawn 0.5.0 candidate".
