## API deltas since the withdrawn 0.5.0 candidate

- `ClaimedDelivery.target_registration_fence: str` — captured in the claim transaction; `revalidate_claim` requires it.
- `FinalizationResult.status` / `CompositeFinalizationResult.status` gain `'altered_retry_rejected'` (same token, different persisted field; zero rows changed). The full set is `finalized | unauthorized | already_finalized | altered_retry_rejected | lease_already_released | receipt_already_won`.
- `leases.pre_adapter_release(next_attempt_at: Optional[int])` — `None` preserves the stored schedule; `CompositeStorage.release_claim` always passes `None`.
- Lease expiry is `clock() + recovery_after`, decided after the write lock; recovery eligibility uses the clock; `now` gates pending due-ness only.
- `claim_delivery` / `pre_adapter_mark` refuse when the snapshot does not describe the facade's claimant, when any `PresenceRecord` field except `heartbeat_at` (so `expires_at` too) or PID/start differs from the current row, when the row is revoked/expired/not in `active|busy|idle`, or when the target's `(tool, wake_capability)` differs from the facade route.
- `apply`: non-canonical v2/v3 sources are `refused` before any backup; after a committed hop, `refused`/`failed` results carry that hop's backup and the actual version; backups are per hop and suffixed `.from-v2` / `.from-v3`.
- `rollback` refuses dispatch witnesses with no `queue_attempts` row matching token and full delivery key, and non-canonical source state.
- `create_backup(..., suffix="")`; `BackupVerificationFailure.path`.
- `leases.pre_adapter_mark(..., target_registration_fence: Optional[str] = None)` — the facade passes `claim.target_registration_fence`; a target whose fence rotated since the claim is refused at the adapter gate even after a re-snapshot.
- `leases.pre_adapter_release` raises `ValueError` for a `next_state` outside `pending`/`blocked`.
- Transaction envelope: SQLite auto-rollbacks (`SQLITE_FULL`, `interrupt()`, I/O errors) leave the consumer's connection open and usable; the connection is closed only when a transaction survives a failed `ROLLBACK`.

## Consumer rule for expiry extensions (ruling R-S)

`expires_at` is compared. If a registration's expiry was extended between the snapshot and the mark, the mark refuses: re-observe and re-snapshot outside the transaction while still owning a valid pre-entry claim, or release to `blocked`. Never auto-retry an entered or ambiguous dispatch. The 30 s proof-age window is a maximum age, not a validity guarantee.

## Migration behavior

Each hop (`v2→v3`, `v3→v4`) runs under `BEGIN IMMEDIATE`: version recheck, exact source schema (artifact set, no managed-namespace extras, canonical SQL text — canonical v2/v3 DDL ships as `schema_v2.sql` / `schema_v3.sql`), quiescence recheck, per-hop backup through a separate read connection, DDL, then exact destination schema + `foreign_key_check` + preserved-table row counts + version row before `COMMIT`. Ordinary errors produce a `failed`/`refused` outcome with this hop's backup (or the unverified file path) and the actual version; a failure after a successful commit reports the destination version; only `KeyboardInterrupt`/`SystemExit` propagate. The v2→v3 hop remains a separately validated step; a refusal in the second hop leaves a valid schema-3 database and reports the first hop's backup.
